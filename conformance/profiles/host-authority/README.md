# Optional host authority profile (SPEC §18)

This profile targets the merged specification at `6bd25e3fcdf068af861aa289903a8489bd8f0139`. It applies only to a host that declares the corresponding authority capability. It does not add authority, a clock, journal, coordinator, archive, or worker to the base evaluator.

`vectors.generated.json` fixes 7 accepted and 15 rejected operation outcomes, 4 valid and 2 invalid profile reports, and 3 valid and 4 invalid signed Unix nanosecond values. It also supplies 7 dispatch/result claim checks, 9 native traces, a permanent scope identity allocation check, and 4 base-core authority refusals. Each operation provides the exact nine-field request bytes, twelve-field raw response bytes, trusted invocation, proposed native mutation bytes, one-attempt fault, and complete before/after ledger observations. Replay retains the original request and first response bytes. The generator derives guarded-commit digests from concrete mutation bytes and recomputes their request and evidence digests; it therefore preserves the normative named outcomes rather than pretending the example's illustrative digest has a known byte preimage. The accepted retirement row similarly binds the exact destination of the conditional PostgreSQL topology example.

The driver must seed the `ledger_before` state through its test setup, invoke the **production** authority adapter once with the supplied `call`, capture its raw response before inspecting state, then observe the authoritative database, checkpoint, journal, worker claims, ingress acknowledgements, freeze inventory, grants, and permanent scope allocation for `ledger_after`. Each native trace supplies closed control actions and ordered calls. The harness must implement the named guard barriers, second session, native outcome observation, process restart, retained-storage observation, fate resolution and old-session fence. It returns exact observed events, including barriers reached, blocked calls, direct response bytes and ledger snapshots. The adapter never receives vector IDs or expected data and must not implement a parallel state machine. `run_host_authority_profile.py --adapter ...` compares these responses and observations with strict UTF-8 JSON, duplicate-member rejection and type-exact equality. A response digest alone is insufficient: successful mutations need a committed receipt retaining complete request/result bytes. Source validation and deterministic generation only prove fixture construction.

The six normative report rows are **hypothetical common-rule examples**, not public certification. The public runner first asks the production adapter for its actual configured report, then verifies its provider closure bytes, configuration bytes, health and native proof IDs against the completed C traces for that same binding. It checks the report again after the probes. This report may claim guarded local writes, worker fencing and complete inventory only when their applicable native probes passed. The runner refuses every `safe_relocation: true` report: the conditional PostgreSQL source example cannot authorize activation or establish a public claim. A separate I2 same-authority transfer suite must demonstrate committed source retirement, known native fate, old-session fencing, exact destination, single-use grant consumption, complete participant import and inactive destination on refusal before any such claim. The C runner always exercises unavailable authority and relocation refusals, including copied-database refusal without that capability.

Native proof for **each claimed topology** must hold the scope guard through its actual SQLite/PostgreSQL commit or rollback, race a second writer and freeze, inject precommit rollback, commit-unknown disconnect/kill, and postcommit lost response, then restart on retained storage. The closed trace controls specify their barrier/fault placement and expected direct response, native fate, restart and storage observations. They must establish exactly one mutation, receipt, and generation advance or a known rollback. Unknown fate blocks frozen inventory, retirement, and activation until storage resolves fate and the old session cannot commit. A separate epoch check followed by root CAS is insufficient.

For a `worker_fencing` claim, the seven claim checks exercise authenticated principal, current epoch/fence, dispatch and result rejection at `now >= expires_at`, and trusted-clock-unavailable refusal. Each fixes the exact journal, checkpoint, claims, acknowledgements and external-dispatch count after the check; rejected checks allow no mutation or dispatch. Expiry of a possible external call leaves ambiguity; it cannot prove no call happened. For `complete_scope_inventory`, enumeration at one frozen point must include roots, tombstones, receipts, pending and terminal intents, journals, definition/migration references, and all required participants. The required journal and worker participants enter **before** the freeze, whose retained record binds the inventory digest to its evidence; retirement resolves that exact record. The allocation check deletes portable checkpoint bytes and then attempts to reuse the same scope identity; the durable authority allocation marker must still refuse it.

Run `python scripts/generate_host_authority_profile.py --spec-root ../determa-state-spec --check`, `python scripts/test_host_authority_validator.py`, and `python scripts/validate_conformance.py --spec-root ../determa-state-spec`. A host claims conformance only after its own native transaction harness runs the applicable matrix and records the configured topology and actual evidence.
