# Optional host authority profile (SPEC §18)

This profile targets the merged specification at `6bd25e3fcdf068af861aa289903a8489bd8f0139`. It applies only to a host that declares the corresponding authority capability. It does not add authority, a clock, journal, coordinator, archive, or worker to the base evaluator.

`vectors.generated.json` fixes 7 accepted and 15 rejected operation outcomes, 4 valid and 2 invalid profile reports, and 3 valid and 4 invalid signed Unix nanosecond values. It also supplies 7 dispatch/result claim checks, 8 native traces, and a permanent scope identity allocation check. Each operation provides the exact nine-field request bytes, twelve-field raw response bytes, trusted invocation, proposed native mutation bytes, one-attempt fault, and complete before/after ledger observations. Replay retains the original request and first response bytes. The generator derives guarded-commit digests from concrete mutation bytes and recomputes their request and evidence digests; it therefore preserves the normative named outcomes rather than pretending the example's illustrative digest has a known byte preimage. The accepted retirement row similarly binds the exact destination of the conditional PostgreSQL topology example.

The driver must seed the `ledger_before` state through its test setup, invoke the **production** authority adapter once with the supplied `call`, capture its raw response before inspecting state, then observe the authoritative database, checkpoint, journal, worker claims, ingress acknowledgements, freeze inventory, grants, and permanent scope allocation for `ledger_after`. A native trace supplies a setup, schedule and ordered calls, including precise fault/barrier injection; the adapter returns direct responses and an independent ledger observation after each call. The adapter never receives vector IDs or expected data and must not implement a parallel state machine. `run_host_authority_profile.py --adapter ...` compares these responses and observations. A response digest alone is insufficient: successful mutations need a committed receipt retaining complete request/result bytes. Source validation and deterministic generation only prove fixture construction.

The production configuration path must supply each profile report from installed B1 provider identity, configured instance health, actual topology, participant closure, and native proof. A schema-valid descriptor or self-reported claim does not prove a configured guarantee. The valid PostgreSQL relocation example is conditional; it does not authorize activation. A host without proved same-authority retirement and exact destination binding must refuse relocation with `host_capability_mismatch` or `scope_fence_unproven` and leave the destination inactive. A copied database is never a grant. An implementation advertising only guarded local writes must leave worker fencing and relocation false unless those native paths are separately proved.

Native proof for **each claimed topology** must hold the scope guard through its actual SQLite/PostgreSQL commit or rollback, race a second writer and freeze, inject precommit rollback, commit-unknown disconnect/kill, and postcommit lost response, then restart on retained storage. The eight trace schedules specify their barrier/fault placement and expected direct response/storage observations. They must establish exactly one mutation, receipt, and generation advance or a known rollback. Unknown fate blocks frozen inventory, retirement, and activation until storage resolves fate and the old session cannot commit. A separate epoch check followed by root CAS is insufficient.

For a `worker_fencing` claim, the seven claim checks exercise authenticated principal, current epoch/fence, dispatch and result rejection at `now >= expires_at`, and trusted-clock-unavailable refusal. Expiry of a possible external call leaves ambiguity; it cannot prove no call happened. For `complete_scope_inventory`, enumeration at one frozen point must include roots, tombstones, receipts, pending and terminal intents, journals, definition/migration references, and all required participants. The allocation check deletes portable checkpoint bytes and then attempts to reuse the same scope identity; the durable authority allocation marker must still refuse it. For `safe_relocation`, the same trusted authority domain must prove known fate, source retirement, old-session fence, exact destination, single-use grant, and complete import. A minimal adapter must run the unsupported relocation trace and refuse it. The `runtime_probes` list names remaining operational proof coverage for the implementation harness; the list alone is not evidence of passing those probes.

Run `python scripts/generate_host_authority_profile.py --spec-root ../determa-state-spec --check`, `python scripts/test_host_authority_validator.py`, and `python scripts/validate_conformance.py --spec-root ../determa-state-spec`. A host claims conformance only after its own native transaction harness runs the applicable matrix and records the configured topology and actual evidence.
